Embedded Developer

The flight-controller firmware and navigation logic on every Vision platform is code you’d be writing and debugging — on real hardware, not a simulator.

Careers
What’s Actually Yours

Firmware that has to work when GPS doesn’t

Our nav stack is built to keep flying in GPS-denied conditions, and that logic lives in firmware you’d be maintaining and extending. Sensor fusion, control loops, the link to the GCS — if it’s running on the flight controller, it’s probably yours to own at some point.

Bugs here show up as a drone doing something unexpected mid-flight, so we test carefully. We’re not looking for someone who’s only worked in simulation.

Flight Controller Firmware Sensor Fusion GPS-Denied Nav
The Stack

What you’d be working in

C / C++ RTOS or bare-metal Sensor fusion (IMU, GPS, barometer) Serial & CAN comms
What This Looks Like Some Weeks

Bench, then field, then back to the bench

Write and bench-test

New firmware gets tested on the bench first, against real sensor data where we can get it.

Fly it

You’re usually there for the test flight, watching telemetry, not just handing off code and waiting.

Fix what the field found

Something always behaves slightly differently outside the bench. That gap is where the real debugging happens.

Ship it

Once it’s solid, it goes into the GCS-delivered update — direct to operators, no app-store review to wait on.
